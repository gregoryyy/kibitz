## PR 109 follow-up review

CodeQL on `31af699` reported a new high file-race alert **22** at `public-files.mjs`'s open, plus medium network-to-file alerts **20/21** at the flipbook's Markdown/JSON writes. The initial feature check was red; runtime regression passes did not establish scanner completion.

- **22 — code correction:** open before any filesystem check, inspect the held descriptor, then validate canonical path/regular-entry identity before reading bytes. The path entry does not authorize a later open. Tests distinguish a replacement before identity validation (404 and close) from a replacement after validation (serve the original descriptor). No file-race alert is dismissed.
- **20/21 — reviewed intended capture data; medium findings remain open:** [the runner](../site/scripts/flipbook.mjs) is an operator-invoked documentation tool. It starts its own loopback gateway, prints the selected provider/task-model plan and checks paid approval before requesting coaching. HTTP/model data supplies report contents, not output filenames. The operator selects a dedicated `--out`; staging uses `mkdtemp`, screenshots use trusted local tour IDs, and the two flagged names are fixed `README.md`/`run.json`. The app never executes these artifacts or treats their contents as trusted code. Coach prose is raw-HTML escaped in Markdown; JSON is serialized as data. Existing [unit cases](../site/tests/unit/flipbook.test.mjs) check escaping/publication rollback and [mock CLI cases](../site/tests/e2e/flipbook.spec.mjs) check no-call preservation and the complete staged capture. Captured prose/model labels remain untrusted; a chosen provider or operator-owned configuration is not a source of executable app code.

The [network-to-file query](https://codeql.github.com/codeql-query-help/javascript/js-http-to-file-access/) explicitly asks for inspection of whether a write is intended; it does not itself establish arbitrary path control. The [file-race query](https://codeql.github.com/codeql-query-help/javascript/js-file-system-race/) recommends using descriptors. Review dispositions apply to these exact sinks and deployment assumptions, without disabling a query or excluding source files. Historical main-branch findings and other contexts in #99 still need their own disposition and resulting scan evidence. Rescanning source `32758c9` marks alert 22 fixed and passes the CodeQL gate while still reporting medium 20/21; success is not a zero-alert result. No alert state was manually changed. Both mock capture/plan CLI tests pass, including all nineteen screenshots and nine placeholder answers in a temporary output directory; the published paid capture remains unchanged.

## Provider capture follow-up (11.2.8)

Context **9** in [#99](https://github.com/gregoryyy/kibitz/issues/99) is an intentional network-response-to-JSON capture, with fixed provider/case filenames and an operator-owned output directory. Contract replay parses JSON as data and supplies the body to an SDK, without evaluating it. The old recorder still had actual defects: implicit inference, unbounded response collection, publication of error bodies and writes through existing destination symlinks. The [recorder](../site/scripts/record-ai-fixtures.mjs) now requires explicit execution after its plan, stages output privately, bounds attempts/bytes/time, refuses invalid/incomplete/known-credential-bearing responses and atomically replaces accepted files. [SDK/filesystem tests](../site/tests/unit/fixture-recording.test.mjs) and [real-CLI regressions](../site/tests/e2e/fixture-recording.spec.mjs) intercept every request with synthetic data. The no-confirmation regression is also run against the actual prior recorder in a disposable copy.

The [capture guide](AI-FIXTURES.md) records limits and manual privacy review: unknown fields/encoded secrets, operator-controlled directory writers and the semantic quality of output are not certified by these checks. Existing paid captures are unchanged; TODO 2.15 remains open. This review neither suppresses the query nor dismisses the historical medium alert. Feature/main scan verification and other #99/release gates remain separate.

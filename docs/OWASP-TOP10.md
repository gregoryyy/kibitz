This maps application code and existing verification to all ten categories. It is an evidence checklist with open findings, rather than a security certification or release approval.

Scope: [the loopback, single-user deployment](DEPLOYMENT.md) and [its threat model](THREAT-MODEL.md). Source snapshot: `220310529f2a0e19681055d496b68cb6110939a1`. An `[x]` below means the category has been mapped and its evidence/remaining work recorded. It does not mean every risk is eliminated. The findings table and TODO 11.3–11.6 remain release gates.

## Evidence and release decision

- Existing checks/build and **566 unit/server passes, one opt-in live skip**, plus five focused bilingual benchmark/capture browser passes, were verified on source snapshot `2203105`. They are useful existing regression evidence; they are not a new exhaustive OWASP browser audit. The latest capture regression also demonstrates why automatic cue scores are not semantic verification.
- The additional synthetic mock-server probe for #96 returned `status: 200` and `bodyStartsWithSQLiteHeader: true`. It used a temporary empty public directory, a separate temporary model directory and a newly created empty usage database with a catalogue filename. The server was stopped and temporary files removed. No provider requests, personal records or model downloads were involved.
- Documentation/code mappings and local links were reviewed for this checklist. Application runtime code is unchanged by this milestone. Future fixes must add their own regression evidence and update finding dispositions.
- **No release approval:** unresolved high-rated scanner alerts and the tracked findings still need resolution/justification. LLM Top 10 test mapping (11.3), ASVS verification (11.4), automated scanner/baseline evidence (11.5) and the release gate (11.6) remain open. Do not copy this checklist into a release PR as an all-clear result.

Before each release, record the exact release commit, supported deployment, actual checks/scan outputs, issue dispositions and remaining limitations. Re-run this mapping when data flows, tool privileges, provider/runtime choices or deployment boundaries change.
